# CFB Pickems audit — 14 October 2026

Read-only pass over the iOS app and the Firebase backend, plus a few small draft fixes. Nothing here was merged, deployed, or uploaded. `firestore.rules` was not edited. Production was not touched.

The September audit's three P0 rules holes (join without a code, forge `seasonWins` by deleting your member doc, rewrite the lock snapshot) are closed **in this repo** and the emulator tests named "P0" pass. I did not compare that file to the live Firestore rules. Treat "closed in git" and "closed in production" as different until someone checks.

## How to read the table

**P0** — cheating or a wrong score a member can cause this Saturday, with no extra condition.
**P1** — wrong score, stuck week, or a trust hole that needs a league setting, a commissioner, or a script.
**P2** — cost, compliance, or a sharp edge that will not mis-score a normal week by itself.
**P3** — hygiene.

| Sev | What | Why it matters | Fix |
|---|---|---|---|
| P1 | ESPN `state: "post"` is treated as a finished game on the server, and not on the phone | `parseEventScores` sets `completed` when the state is `"post"`, even if ESPN's completed flag is false. A postponed or canceled game that still has score strings (often `"0"`) is marked final. Against a point spread, 0–0 is a real result: the dog covers. The phone only looks at the completed flag, so it can still show the game as scheduled. If the scores are missing, the game never goes final and the whole week waits forever, because scoring requires every slate game to be final. | Read the status name (`POSTPONED`, `CANCELED`, `DELAYED`). Do not treat `"post"` alone as final. Skip those games so the rest of the week can score. The result to show is an owner decision below. |
| P1 | The line that gets graded is whatever is on the game doc at score time | Picks do not store a spread. The slate copies the line when the game is created, and a commissioner can change `spread` / `spreadTeamId` later, including after the game is final. The next scoring pass uses the new number. A 7-point push becomes a cover if someone moves it to 6.5. ESPN refreshes do **not** overwrite that field. | Freeze the line when the week opens, or copy it onto the pick at submit. Reject later edits in rules. Owner decision below. |
| P1 | A bad spread grades as the away team | `Math.abs(NaN)` is `NaN`, and `NaN > 0` is false, so the away side "covers" a 35–0 home win. A nomination can still store a non-numeric spread. Rules do not check the field. | If the spread is not a finite number, skip the game. Same check in Swift and TypeScript. |
| P1 | A final that happens before the lock never notifies | The first pass stamps the game final and may skip the "game final" and "no pick" pushes because kickoff has not passed. The next pass sees `prevStatus === "final"` and will not send, even when `finalNotifiedAt` was never set. A rescheduled game, a bad kickoff, or a string kickoff (ignored, so the game never looks locked) drops both pushes for good. | Claim the notification only once the game is locked, and let a later pass send if it was never claimed. |
| P1 | The person who wrote a chat message can un-hide it | Confirmed on the Firestore emulator: commissioner sets `isDeleted: true`, the author sets it back to `false`. The author allow-list includes `isDeleted`. | Take `isDeleted` off the author's update list. Rules change. Not done here. |
| P1 | [PR #75](https://github.com/johnmfanning1-svg/Pickems/pull/75) is still open, so rules still accept a kicked-off Selection | The app build on main refuses a game that has already started. The rules on main do not. A script can write the selection with a kickoff in the future. #75 checks the kickoff on the document, which the client supplies, so a forged future time still works after that PR. | Owner decision below. A real fix also checks the kickoff on the server against ESPN. |
| P1 | Late-pick leagues can dodge the penalty | If `allowLatePicks` is on, rules allow pick writes for the whole `picking` window, and `submittedAt` is whatever the client sends. Backdating it skips the win penalty. Pick docs are otherwise unchecked: confidence game, display name, and which games are in `picks`. | Stamp `submittedAt` from `request.time`, or have the function ignore the client timestamp. |
| P1 | The 5-minute scorer reads every league, and one ESPN miss stalls that slate | `lockAndScoreWeeks` loads every group, then every picking/locked week. A failed scoreboard fetch is swallowed as an empty list, so those games never update. There is no retry or backoff. Rolling-lock rules unroll 20 games and can hit Firestore's 1000-expression cap (the emulator log showed that denial on a pick update). Games past the 20 stored kickoffs are not checked. | Isolate leagues so one bad doc does not matter. Retry ESPN with backoff. Move per-game lock checks out of the rules expression. |
| P2 | Season ties were using this week's picks | Head-to-head on the season board used the open week's slate, so one Saturday could reorder a season tie. The January champion job breaks that tie by join date, then name. [PR #86](https://github.com/johnmfanning1-svg/Pickems/pull/86) stops passing this week's games into the season ranking. The widget still does not apply weekly head-to-head, because it never loads picks. | Review #86. Widget head-to-head is a follow-up if the phone and the widget must match. |
| P2 | Account deletion does not meet Apple's Sign in with Apple rule | `deleteAccount()` still does not call `revokeToken`. It deletes the profile, handle, and avatar before `user.delete()`, so a failure leaves an Auth user with no profile. Picks, chat, and career docs keep the name. Guideline 5.1.1(v). | Revoke the Apple token, delete the Auth user, then have a function anonymize authored docs. |
| P2 | Widget and watch had no privacy manifest | Both read the App Group with `UserDefaults`. Only the app declared `CA92.1`. [PR #87](https://github.com/johnmfanning1-svg/Pickems/pull/87) adds the manifests. | Merge before the next archive. |
| P2 | Pull requests did not build or test the app | TestFlight runs on a tag or a manual click and does not run unit tests. The Firebase workflow tests functions only when `firebase/**` changes, and a push of that path to `main` deploys. [PR #88](https://github.com/johnmfanning1-svg/Pickems/pull/88) runs the presentation lint and the functions unit tests on every pull request. It does not deploy. Swift tests still need a Mac runner. | Add a Mac job when you want `PickemsTests` in CI. |
| P2 | Home kept polling ESPN after you left | Game days poll every 15 seconds from 10:00 to 23:00 Eastern, otherwise every 60. The fetch is the full scoreboard (`groups=80`, `limit=300`) with no backoff. Home's stop function had no caller. [PR #89](https://github.com/johnmfanning1-svg/Pickems/pull/89) pauses that loop off the Home tab and in the background. The in-memory cache is 60 seconds for live and 15 minutes for browse. A schema change that drops `competitions` makes the parser return nothing and the week sit still. | Keep #89. Add backoff on HTTP errors. |
| P2 | Any signed-in user can read an invite code they can guess | `get` on `inviteCodes/{code}` is allowed. Codes are 4–8 characters. There is no rate limit. Listing the collection is denied. | Longer codes, or a callable that rate-limits guesses. |

Swift package pin is Firebase iOS SDK 11.15.0. No SwiftLint config. | Upgrade on its own branch. Do not `npm audit fix --force` on main. |
| P2 | Client config is committed. No private key was found. | `GoogleService-Info.plist` is at the repo root and in `Pickems/`. `firebase/admin/.env.production` has the web Firebase config (API key, project id, app id). PEM blocks in the TestFlight workflow and the App Store script are instructions and tests, not a checked-in `.p8`. | Do not add a service-account JSON. Leave the values where they are. |

That returned in August and September. The current Settings screen uses one sheet on the screen root (`CommissionerSettingsView`), which matches `docs/PRESENTATIONS.md`. The presentation lint passes. I could not tap it on a device. The remaining way the whole sheet closes by itself is the force-update binding: if `minimumBuild` blocks the app, every sheet is set to nil. A brief missing league no longer does that. | If it still happens on 3.6.3, note which sheet (spread editor, members, deadline) and the Firestore write that landed. |

Group, pick, and chat listeners are removed on sign-out or when the screen goes away. `LiveAppConfigService` never removes its listener. It lives for the process. | Optional: stop that listener on sign-out. |
| P3 | Dynamic Type and VoiceOver | Commissioner rows have labels. Several hero marks use a fixed size (sign-in at 64pt, a few empty states). Share cards are fixed because they are images. Home shows a banner when ESPN fails. There is no offline queue for a pick that could not be saved. | Let the hero marks scale. A failed pick write should stay on screen until it lands. |

Straight Up, half-point spreads, pick'em pushes, and confidence scoring match between `ScoringEngine.swift` and `scoring.ts` for the cases added in [PR #85](https://github.com/johnmfanning1-svg/Pickems/pull/85). A half-point line does not push. A confidence push counts once. A missed pick on a final game is one loss, not a push. Kickoff lock uses the UTC instant, so daylight saving does not move it. A kickoff stored as a plain string is ignored, which means that game does not lock on its own.

## What a member cannot do

Checked against `firebase/firestore.rules` and the emulator:

- Edit another member's picks.
- Write `standings`, `seasons`, or `career`.
- Edit another member's name or season record.
- Rewrite the week's lock snapshot.
- Join a league without the current invite code.

A commissioner can still edit another member's picks while the week is locked, change a final game's spread, and write standings. That is the current rule, not a member hole.

## Decisions only you can make

1. **Postponed and canceled games.** Skip them so the rest of the week scores, or hold the week until every game is final. Do not grade a 0–0 that ESPN did not mark complete. The phone and the server disagree on this today.
2. **When the spread is frozen.** Keep grading the line on the game (set when the slate is built, and a commissioner can still change it after kickoff), or copy the line onto each pick at submit and ignore later edits.
3. **Whether to merge [#75](https://github.com/johnmfanning1-svg/Pickems/pull/75).** The app already refuses a kicked-off Selection. The rules do not, and merging that PR deploys them. A forged future kickoff still gets through either way until the server checks ESPN.
